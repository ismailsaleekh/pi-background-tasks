# Issue 19: new Function('return import(...)') cannot work in pi's compiled binary (Bun) — delegation fails for non-Anthropic providers
Author: KorepanovSA (NONE)
State: open; Created: 2026-09-15T05:20:20Z; Updated: 2026-09-15T05:20:20Z
URL: https://github.com/ismailsaleekh/pi-background-tasks/issues/19

**Package:** `pi-background-tasks` 2.5.0
**Pi:** 0.85.1 (Linux x64), distributed as a **Bun v1.3.14 single-file compiled binary** (`bun build --compile`).

## Summary

`src/core/anthropic-attribution.ts` (line 2499 in the shipped build) loads the built-in Anthropic
implementation for non-target providers through a `new Function` dynamic import:

```ts
const dynamicImport = new Function('specifier', 'return import(specifier)') as
  (specifier: string) => Promise<{ streamSimpleAnthropic: (...) => AssistantMessageEventStreamLike }>;
const mod = await dynamicImport('@earendil-works/pi-ai/anthropic');
```

In the shipped pi binary this always throws, so any stream that reaches `forwardToBuiltInAnthropic`
ends with `stopReason: 'error'`:

```
Anthropic attribution could not delegate non-target provider "minimax": A dynamic import callback was not specified.
```

Verified directly in the same pi build with a test extension:

```
[DYNIMP] FAIL A dynamic import callback was not specified.
```

`new Function(...)` bodies are compiled by `eval`-like machinery that has no dynamic-import callback
registered; a statically analysable `await import('@earendil-works/pi-ai/anthropic')` (or a normal
top-level import / lazy `import()` in a module) works fine.

## Impact

`pi-background-tasks` registers its Anthropic provider **globally**, so the wrapper is reachable by any
consumer that resolves a stream handler from the provider registry. One concrete victim: with
`pi-observational-memory` 3.1.x, the observer/reflector/dropper resolve their stream by matching
`config.api === model.api`, so a model like `minimax/MiniMax-M3` (`api: anthropic-messages`,
provider `minimax`) is routed into this wrapper and every consolidation run fails with the error above —
observational memory silently stops recording.

## Suggested fix

Use a real dynamic import instead of `new Function`, e.g.:

```ts
const dynamicImport = (specifier: string) => import(specifier);
```

(or a static `import { streamSimpleAnthropic } from "@earendil-works/pi-ai/anthropic"` if the package
should always be loaded), and keep the error handling as is.

Separately, consider guarding the override so it only intercepts its own provider id — providers with
`api: anthropic-messages` but a different provider id (minimax, kimi-coding, …) should not be routed
through the Anthropic attribution path.
