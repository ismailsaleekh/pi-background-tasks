# Issue 21: perf: Cold startup delay on Windows due to unbundled TypeScript entries & eager imports (~530ms)
Author: 821869798 (NONE)
State: open; Created: 2026-09-17T08:37:45Z; Updated: 2026-09-17T08:37:45Z
URL: https://github.com/ismailsaleekh/pi-background-tasks/issues/21

### Environment
- OS: Windows 11 (NTFS)
- Pi version: 0.85.1
- Package: `pi-background-tasks` (v2.5.0)

### Problem Description
Profiling Pi startup latency reveals that `pi-background-tasks` adds **~533 ms** to every cold start on Windows, even when no background tasks or child processes are active.

There are two primary factors contributing to this overhead:

1. **Unbundled TypeScript in npm distribution**:
   `package.json` registers two raw `.ts` extension entrypoints:
   ```json
   "pi": {
     "extensions": [
       "./extensions/anthropic-attribution.ts",
       "./extensions/background-tasks.ts"
     ]
   }
   ```
   Because the npm package only distributes uncompiled `.ts` files, Pi's Jiti runtime must dynamically parse and transpile the entire TypeScript source tree on every startup. On Windows NTFS, filesystem metadata lookups make this noticeably slow.

2. **Eager static imports in `src/extension.ts`**:
   At registration time, `src/extension.ts` statically imports heavyweight feature modules at the top level:
   - `fusion-extension.ts` (~49 KB)
   - `delegate-extension.ts` (~35 KB)
   - `ui/background-tasks-manager.ts`
   This pulls the full AST and dependency graph of Fusion and Delegate subsystems into memory at startup, even if the user only uses basic background tasks (as also discussed in #20).

### Benchmark Numbers (Windows 11)
- Baseline Pi startup (clean, `--no-extensions`): **~550 ms**
- With only `pi-background-tasks` loaded: **~1,085 ms** (+535 ms overhead)

### Suggested Improvements
1. **Ship pre-compiled JavaScript**: Pre-build the TypeScript sources to plain `.js` (e.g. via `tsc` or `tsup`) before publishing to npm, pointing `pi.extensions` to the compiled `.js` files.
2. **Lazy-load Fusion & Delegate**: Defer loading `fusion-extension` and `delegate-extension` via dynamic `await import(...)` when their corresponding commands or tools are actually invoked.
