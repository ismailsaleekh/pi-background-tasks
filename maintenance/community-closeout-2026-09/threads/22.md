# PR 22: perf: defer heavy execution modules until tool/command invocation

## Overview
Resolves #21.

This PR optimizes cold startup latency by deferring heavy execution modules until tools or commands are actually invoked, keeping top-level registration lightweight and fast without altering public schemas, tool definitions, command contracts, or adding external build steps.

### What is optimized
1. **`src/extension.ts`**:
   - Defer loading `BackgroundTasksManager` (`./ui/background-tasks-manager.js`) until `/bg` or dock UI is opened.
2. **`src/fusion-extension.ts`**:
   - Retain all tool definitions (`fusion_reason`, `fusion_investigate`, `fusion_research`, `fusion_validate`) and schemas at top-level so Pi and LLMs discover them immediately.
   - Defer importing heavy workflow execution modules (`FusionOrchestrator`, `context.js`, `clean-context.js`, `config.js`) until a fusion workflow or `/fusion` command actually runs.
   - Defer importing `FusionModelSelector` until `/fusion-models` command is invoked.
3. **`src/delegate-extension.ts`**:
   - Retain `bg_delegate` and `bg_result` schemas at top-level.
   - Defer importing delegate launch & runner modules (`runner.js`, `launch.js`, `result-package.js`) until `bg_delegate.execute` or `bg_result.execute` is executed.
4. **Docs Parity**:
   - Regenerated documentation via `npm run docs:generate` to keep line numbers and contracts in sync.
