# Issue 16: Shortcut conflict: shift+down also registered by @osolmaz/pi-workflows (widget scroll loses)
Author: jeffbking (NONE)
State: open; Created: 2026-09-10T00:00:45Z; Updated: 2026-09-10T00:00:45Z
URL: https://github.com/ismailsaleekh/pi-background-tasks/issues/16

When both `pi-background-tasks` and `@osolmaz/pi-workflows` are installed, pi reports at startup:

> Extension shortcut conflict: 'shift+down' registered by both .../pi-workflows/src/extension/index.ts and .../pi-background-tasks/extensions/background-tasks.ts. Using .../pi-background-tasks/...

Pi keeps only the last registration, so the pi-workflows widget scroll-down binding silently stops working (and the startup warning persists forever).

**Repro:** install both packages, start pi.

**Suggestion:** make the dock shortcut configurable (env var / settings flag, e.g. `PI_BG_DOCK_SHORTCUT`), or pick a default that doesn't collide (e.g. keep `shift+down` documented but allow override). Happy to PR either approach — let me know which you'd prefer.

Environment: pi 0.85.1, pi-background-tasks 2.5.0, @osolmaz/pi-workflows 0.16.10.
